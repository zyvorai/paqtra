## Quick Start

### 1. Configuration Files

Choose a configuration template based on your environment:

**Development** (permissive, fast iteration):
```bash
cp examples/configs/development-config.yaml ~/.config/cilium-vision/config.yaml
```

**Production** (conservative, high confidence):
```bash
cp examples/configs/production-config.yaml ~/.config/cilium-vision/config.yaml
```

**Default** (balanced):
```bash
cp examples/configs/default-config.yaml ~/.config/cilium-vision/config.yaml
```

### 2. Example Policies

The `policies/` directory contains CiliumNetworkPolicy examples generated by Cilium Vision's AutoPolicy feature with ML confidence scores.

Apply an example policy:
```bash
kubectl apply -f examples/policies/allow-frontend-backend.yaml
```

View policy in TUI:
```
./cilium-tui
Press Tab to navigate to "Policies" tab
```

The `scenarios/` directory contains step-by-step guides for common use cases:

- **[chaos-gameday.md](scenarios/chaos-gameday.md)** - Run chaos engineering GameDays

## Configuration Options Explained

### AutoPolicy Settings

```yaml
autopolicy:
  learning_duration_secs: 604800  # How long to observe traffic
  min_observations: 10            # Minimum flows before policy generation
  auto_generate: false            # Auto-generate vs manual approval
  ml_confidence_threshold: 0.75   # Minimum confidence for recommendations
```

**ML Confidence Levels**:
- **90-100%**: Very High - Safe for production ✅
- **75-89%**: High - Test in staging first ✓
- **60-74%**: Medium - Use audit mode ⚠️
- **<60%**: Low - Manual review required ❌

### Chaos Engineering Settings

```yaml
chaos:
  max_drop_rate: 0.5              # Max 50% packet loss
  max_latency_ms: 5000            # Max 5 second delay
  require_confirmation: true      # Ask before running experiments
  circuit_breaker_enabled: true   # Emergency stop available
```

**Safety Limits**:
- Development: High limits (80% drop, 10s latency) for aggressive testing
- Production: Low limits (10% drop, 1s latency) for controlled experiments

### Canary Deployment Settings

```yaml
canary:
  initial_traffic_pct: 10         # Start with 10% traffic
  traffic_step_pct: 10            # Progress in 10% increments
  auto_promote_threshold: 0.99    # Promote if 99%+ success
  auto_rollback_threshold: 0.90   # Rollback if <90% success
```

**Thresholds**:
- Development: Aggressive (95% promote, 85% rollback)
- Production: Conservative (99.5% promote, 95% rollback)

## Policy Examples Explained

### 1. Frontend → Backend Communication

[allow-frontend-backend.yaml](policies/allow-frontend-backend.yaml)

Generated with **95.2% ML confidence** after observing 1,247 flows over 7 days.

**What it does**:
- Allows frontend pods to reach backend pods on port 8080
- Permits GET and POST HTTP methods
- Only allows `/api/*` paths

**Use case**: Standard microservice communication

### 2. DNS Egress

[dns-egress.yaml](policies/dns-egress.yaml)

Generated with **98.7% ML confidence** (very high).

**What it does**:
- Allows all pods to reach kube-dns
- Allows queries to public DNS (8.8.8.8, Cloudflare)
- Permits UDP port 53 traffic

**Use case**: Essential for service discovery

### 3. Database Access Control

[database-access.yaml](policies/database-access.yaml)

Generated with **92.3% ML confidence** after 14 days of learning.

**What it does**:
- Allows only API pods to reach PostgreSQL on port 5432
- Explicitly denies all other ingress
- Includes production environment label matching

**Use case**: Secure database access, zero-trust

## Tips for Getting Started

1. **Start with Development Config**
   - Lower thresholds and faster iteration
   - Auto-generate policies to see how it works
   - Experiment with chaos engineering safely

2. **Progress to Default Config**
   - Balanced settings for staging environments
   - Manual policy approval for safety
   - Moderate chaos limits

3. **Production Config for Live Systems**
   - High ML confidence thresholds (90%+)
   - Conservative chaos limits
   - Frequent health checks and monitoring

4. **Read the Scenarios**
   - Step-by-step guides for real use cases
   - Keyboard shortcuts and best practices
   - Expected outcomes and troubleshooting

5. **Customize for Your Environment**
   - Adjust ML weights based on your traffic patterns
   - Set canary thresholds based on SLOs
   - Configure namespace trust levels
