Paqtra — Release Notes

Changelog and version history

v2.2.0 September 2026 Current Release
Features
  • Installer CLI — curl | sh or brew install, then paqtra install. The Helm chart is built in (CLI vX installs chart vX); --with-cilium sets up Cilium, Hubble and Relay first
  • Operate from one binary — status --wait (exit 1 when unhealthy), doctor, connectivity test, sysdump (redacted; never reads Secrets), upgrade, config, hubble, ui, uninstall --purge
  • Verified releases — static Linux and macOS binaries, sha256sums.txt, cosign signature, SBOM, chart on OCI, multi-arch images including the agent image
  • Rule-level policy editing — add, edit and delete single CiliumNetworkPolicy rules with dry run and concurrency checks; alert rule CRUD
  • Cilium Insights — enabled features, Hubble node health, Hubble and Cilium metrics, BGP v2 / LB-IPAM / Gateway API views, read-only agent queries
Fixes
  • Drop statistics — forwarded traffic was reported as tens of millions of drops; only reasons ≥ 130 are drops now, named from Hubble’s enum
  • kubectl exec -l — five invalid calls (ClusterMesh, WireGuard, NAT/CT counts) now resolve an agent pod
  • Agent image — the chart’s default agent image is now actually published
v2.1.0 September 2026
Features
  • Follow-stream ingest — continuous Hubble Observer gRPC with gap/disconnect visibility on /health
  • Real DNS L7 — query, rcode, answers, latency; never invents SERVFAIL from a policy drop
  • Why denied? — POST /investigate/flow from a DROPPED flow (identities, CNP/CCNP, drop reason, draft allow)
  • Chart default HUBBLE_MODE=grpc — CLI only as an explicit escape hatch
v2.0.0 September 2026
Features
  • Investigate Path — confidence-tagged path reports (observed | inferred | unavailable) from Hubble flows, EndpointSlices, and Cilium policies
  • SQLite flow store — continuous Hubble ingest with query APIs and offline golden CI
  • Hubble Observer gRPC — native gRPC flow collection with CLI fallback (HUBBLE_MODE=grpc|cli|auto)
  • Evidence-backed simulate — policy simulation without speculative allow
  • Read-only boundary — removed map-writing / program-attach eBPF code; map reads via bpftool

Features
  • Web Dashboard — 64 pages built with React 19 + TypeScript, styled with Tailwind CSS dark theme
  • REST API — 75+ endpoints powered by Rust/Axum with full JWT authentication and RBAC
  • Real Kernel eBPF Data — live views of kernel eBPF state via bpftool: Conntrack Table, Policy Map, IP Cache, LB Map, and Drop Analytics (117 programs, 132 maps, 12K+ conntrack entries from real kernel)
  • eBPF Profiler with Map Explorer — upgraded profiler tab with Map Explorer for browsing raw eBPF map entries directly from the kernel
  • Terminal TUI — 13-tab interactive terminal interface with 32K lines of Rust
  • Visual Rule Builder — form-based policy creation with drag-and-drop rule composition, eliminating the need to write YAML manually
  • Full Policy CRUD — create, edit, update, delete, and bulk operations on Cilium network policies
  • Auto-refresh — all views refresh every 30 seconds with DataFreshness indicators showing data age
  • Data Export — CSV and JSON export available on all tabular data views
  • Concurrent Health Checks — parallel health probes with 3-second timeout per target
  • CT Entry Parsing — conntrack entries parsed with real TCP flags and lifetime fields
  • SPA Fallback — the API server serves the React SPA with proper client-side routing fallback
  • K3s Deployment — automated deployment script with built-in smoke tests
  • Client Presentation — 13-slide HTML presentation for stakeholder demos
Security Hardening
  • RBAC enforcement on all destructive operations (policy CRUD, node drain, chaos, healer, rollback)
  • WebSocket connection limiting — maximum 100 concurrent connections to prevent resource exhaustion
  • Rate limiter hardening — periodic bucket cleanup every 60s, mutex poisoning recovery
  • YAML injection prevention — yaml_escape() applied across all policy generation paths
  • JWT secret enforcement — minimum 32-character secret required at startup
  • Input validation — RFC 1123 DNS name validation on all Kubernetes resource names
55 Security Fixes
  • ConfigMap overwrite — fixed destructive overwrite that could destroy Cilium agent configuration
  • CIDR matching false positives — corrected identity resolution logic for overlapping CIDR ranges
  • Path traversal in replay storage — sanitized file paths to prevent directory escape
  • Division-by-zero — fixed 5 locations in anomaly detection scoring where zero denominators caused panics
  • Terminal not restored on panic — added panic hook to restore terminal state before unwinding
  • Unsafe close(0) — prevented closing stdin by adding fd validity guard (fd > 2)
  • API route mismatches — fixed 25+ endpoints where frontend paths did not match backend routes
  • Policy verdict logic — corrected allow/deny determination that was inverted for certain policy types
  • Chaos confirmation bypass — enforced confirmation step that could previously be skipped via direct API call
  • Index-out-of-bounds — fixed array access panics in multiple TUI views when data was empty
Known Limitations
  • WebSocket /ws/flows and /ws/metrics streams require a running Hubble relay instance; without it, streams return no data
  • Server-side pagination is not yet implemented for large datasets; all results are returned in a single response
  • JWT tokens are validated at WebSocket upgrade time but are not re-validated during the lifetime of an open connection; token expiry during a session does not terminate the stream
Roadmap

For the full development roadmap, planned features, and contribution guidelines, see the project README.

  • Token refresh and re-validation for long-lived WebSocket sessions
